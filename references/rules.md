# 判定规则全文

规则编号规则：`S` 筛选、`D` 去重、`O` 排序、`U` 更新。代码中对应位置有同号注释。

---

## S — 筛选

### S1 类型筛选

- 默认 `--types 专辑`，只保留曲库标注为 `专辑` 的条目。
- `Single`（单曲碟，通常 1 首）、`EP`（2–6 首）、`精选集` 默认排除。
- 理由：单曲碟与精选集不是「新作」，重复收录已有曲目会稀释时间线。
- 例外：`--types 专辑,EP` 可纳入 EP；`--types all` 纳入全部类型（一般只用于调研）。

### S2 关键词排除

专辑名**子串命中**以下任一词即整张跳过（默认词表）：

```
演唱会 音乐会 拉阔 现场
Concert Tour Dome Unplugged
精选 精选集 合辑 Greatest "Best of" Anthology Collection
伴奏 Instrumental Karaoke 翻唱 Tribute Cover Remix
原声带特辑
```

- 匹配不区分大小写。
- `--keep-all` 关闭本条与 S3。
- `--exclude "自定义词1,自定义词2"` 覆盖默认词表（完全替换，不是追加）。

### S3 Live 判定（防误杀）

`Live` **不做子串匹配**（会误杀 `ALIVE`、`Deliver`、`Live For Today`），而是用「前后不能是英文字母」的词边界判定：

```regex
(?<![a-z])live(?![a-z])
```

| 专辑名 | 判定 | 原因 |
|---|---|---|
| `Get A Life (Live)` | 现场 | 前方是 `(`，后方是 `)` |
| `台北市立体育场Live全纪录` | 现场 | 中文不是英文字母，边界成立 |
| `D.N.A LIVE 创记录音` | 现场 | 前后是空格 |
| `MOOV Live 2009 陈奕迅` | 现场 | 前后是空格/数字 |
| `ALIVE` | 保留 | 前有 `A`，边界不成立 |
| `Deliver` | 保留 | 前有 `r` |
| `Live For Today`（陈奕迅 2003 正式专辑） | 保留 | 命中白名单 `LIVE_WHITELIST` |

白名单机制：`LIVE_WHITELIST = ("live for today",)`，用于放行名字里带 Live 但确为录音室专辑的作品。新增白名单时请同时补 `references/troubleshooting.md` 的案例。

### S4 演唱者过滤

- 曲目演唱者列表**不包含**本歌手名 → 剔除，计入「跳过他人演唱」。
- 判定为双向包含：`陈奕迅 == 陈奕迅`、`陈奕迅 in 陈奕迅 Eason Chan`、`陈奕迅 Eason Chan in 陈奕迅` 均视为本人。
- 目的：清理「我写给别人唱」的合作合辑。典型例子——周杰伦《Partners 拍档》13 首里 8 首由许茹芸、温岚、古巨基演唱，全部剔除。
- `--include-featured` 关闭本条。

### S5 原声带排除

- 专辑名含 `原声带` / `原声` / `OST` / `Soundtrack` / `电影` / `电视` → **整张跳过**。
- 理由：电影/剧集原声带里，除了少数有词主题曲，大量是几十秒的过场配乐，混进歌单后听感割裂。歌单的用途是「按时间线回顾作品」，不是听配乐素材。
- 跳过的整张会记入「无曲目入选」，并在歌单的「筛选依据」里写明原因，便于回溯。
- `--keep-interludes` 恢复旧行为（原声带按本人占比 ≥30% 保留，且不做演唱者过滤）。
- 典型影响：周杰伦 233 首 → 175 首（《不能说的秘密》24 首 +《天台》33 首整张排除）。

### S5.1 短序曲排除

- 曲目**整名**仅由 `Intro` / `Outro` / `Interlude` / `Prelude` / `序曲` / `前奏` / `开场` / `间奏` 构成（可带编号）→ 剔除。
- 只匹配整名：`Introduction to XXX` 这类正式曲目不受影响；`Intro (Live)` 交由版本规则处理。
- `--keep-interludes` 同时关闭本条。

### S6 曲目下限

- `--min-tracks N`：专辑曲目总数 < N 则整张跳过。
- 与 S1 的区别：S1 按类型（平台标注），S6 按实际曲目数（更可靠地滤掉单曲碟）。

## D — 去重

### D1 专辑级去重（同专辑多条记录）

曲库对同一张专辑可能返回多条记录，特征：

- 同名但 `id` 不同、`size` 不同
- 常见于 Deluxe 版、平台重复上架

处理：按 `归一化专辑名` 分组，每组保留 **`size` 最大**的一条，其余丢弃。

归一化规则：去括号内容 → 去 `remaster(ed)` / `deluxe` / `expanded` / `edition` → 去标点空白 → 小写。

### D2 曲目级去重（跨专辑同名歌）

- 键 = 归一化歌名：去括号内版本后缀 → 转半角 → 去标点空白 → 小写。
- 若键已出现，丢弃当前记录，保留**更早处理**的那条。
- 由于处理顺序按发行时间升序，等价于「保留最早专辑中的版本」。
- `--no-dedupe` 关闭本条，同一首歌会在多个专辑重复出现。

**归一化示例**

| 原歌名 | 归一化键 |
|---|---|
| `晴天` | `晴天` |
| `晴天 (Live)` | `晴天` |
| `晴天（伴奏）` | `晴天` |
| `Love Story (Taylor's Version)` | `lovestory` |

### D3 版本择优（正式版优先）

问题：`Remastered`、`Deluxe`、`Edited Rough Mix` 版可能比正式版**更早发行**，若按时间顺序处理，会先占位，导致正式版整张被判为「重复」而清空。

实例：陈奕迅《上五楼的快活 - EDITED ROUGH MIX》发行于 2009-09-09，正式版《上五楼的快活》为 2009-09-23。按时间升序，混音版先占位，正式版 11 首全部被判重复。

处理：分两轮抓取——

1. 第一轮：专辑名**不含**版本修饰词的（正式版）
2. 第二轮：含 `remaster/deluxe/edited/rough mix/expanded/bonus/special edition/anniversary/重制/纪念版` 的

第二轮撞歌时自动让位给第一轮。最终输出再按时间重排（O3），不影响顺序。

### D4 保留策略开关

| 参数 | 效果 | 适用 |
|---|---|---|
| 默认 | D1 + D2 + D3 全开 | 通听场景，无重复 |
| `--no-dedupe` | 关闭 D2 | 逐张专辑精听，允许重复 |
| `--keep-all` | 关闭 S2 + S3 | 想连现场/精选一起收 |

## O — 排序

### O1 专辑排序

- 键：`(publishTime 升序, 专辑名 升序)`
- 专辑名为兜底键，保证同日发行的多张专辑顺序稳定、可复现（避免每次运行顺序抖动）。

### O2 专辑内排序

- 键：`track no` 升序。
- 曲序缺失（`no` 为 0）时排在该专辑末尾。

### O3 输出重排

抓取阶段因 D3 被打乱顺序，输出前统一按 `(publishTime, 专辑在已排序列表中的下标, 曲序)` 重排一次，恢复严格时间线。

## U — 更新

### U1 全量重建（推荐）

- 直接重跑同一命令，同名文件**幂等覆盖**，不会追加、不会产生重复条目。
- 成本：单歌手 20–60 秒（约 30–100 次只读请求，请求间隔 0.3s）。
- 适用：季度/半年一次的例行更新。

### U2 增量模式

```bash
python3 scripts/build_discography.py "五月天" --since 2025-01-01 --outdir ./增量
```

- 只处理 `publishTime >= since` 的专辑。
- 注意：去重集合从空开始，因此增量结果里可能包含与旧专辑重复的曲目，需人工判断。

### U3 与平台歌单的协同

平台「文字导入」是**新建歌单**，不是追加。所以：

1. 增量产出的是「新增曲目清单」
2. 想保持歌单完整 → 用全量文件重建一次（U1）
3. 想手工补 → 在平台内逐首搜索添加增量清单

### U4 字段兼容

- 新增字段只追加在 CSV **末尾**，不改既有列序。
- 字段删除或语义变更需升 `version` 主版本号，并在 README 记录迁移说明。

## 规则优先级

冲突时的判定顺序：

```
S1 类型 → S2/S3 关键词 → S6 曲目下限 → D1 专辑去重 → S4 演唱者 → S5 原声带豁免 → D2 曲目去重 → O1–O3 排序
```

说明：

- S4 与 S5 的冲突由 S5 优先（原声带整张保留）。
- S2 与 S5 的冲突：`原声带特辑` 在黑名单，但纯 `原声带` 不在，故电影原声带默认保留。
