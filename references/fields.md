# 歌单字段说明

## 1. 主表字段（`<歌手>_歌单.md` / `.csv`）

| 字段名（CSV 表头） | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `序号` | int | 是 | `42` | 歌单内全局顺序，从 1 开始。等于最终播放顺序，可直接用于「第几首」定位 |
| `歌曲` | str | 是 | `富士山下` | 曲目原名。**不剥离版本后缀**：`(Live)`、`(Remix)` 原样保留，避免与正式版混淆 |
| `专辑` | str | 是 | `What's Going On...?` | 所属专辑名，与曲库标注一致 |
| `发行日期` | date | 是 | `2006-11-17` | 专辑首发日期，`YYYY-MM-DD`。缺失时为空字符串 |
| `发行年份` | int | 是 | `2006` | 由 `发行日期` 截取前 4 位。跨年专辑以发行日为准 |
| `类型` | enum | 是 | `专辑` | 曲库标注的专辑类型，取值：`专辑` / `EP` / `精选集` / `Single`（默认已过滤） |
| `专辑内曲序` | int | 是 | `3` | 原始 track number。同专辑内保证与实体碟顺序一致 |
| `演唱者` | str | 是 | `陈奕迅` | `--singers primary` 时写首位歌手，`full` 时用 `/` 连接全部 |

### 字段设计说明

- **为什么同时留 `发行日期` 和 `发行年份`**：排序用日期（精确到天，避免同年多张专辑顺序错乱），人读与按年筛选用年份。只留年份会丢失同年专辑的相对顺序。
- **为什么保留 `专辑内曲序`**：专辑内部顺序是创作意图的一部分，缺失时无法复原「概念专辑」的听感。
- **为什么 `歌曲` 不清洗后缀**：`《晴天》` 与 `《晴天 (Live)》` 是不同录音，清洗后会造成导入时误匹配。

## 2. 导入清单字段（`<歌手>_导入.txt`）

单列纯文本，每行一首，格式固定：

```
<歌曲> - <演唱者>
```

示例：

```
时代曲 - 陈奕迅
伤信 - 陈奕迅
富士山下 - 陈奕迅
```

**格式约束**

- 分隔符为 `空格-空格`（` - `），不是中文破折号
- 一行一首，不写序号、不加引号、不写专辑
- 顺序与主表 `序号` 完全一致
- UTF-8 无 BOM（部分平台对 BOM 敏感）

**为什么只写歌名+歌手**：主流平台的「文字导入」按「歌名 + 歌手」模糊匹配曲库，带专辑或序号会干扰匹配。

## 3. Markdown 文档结构

```markdown
# <歌手> · 专辑全曲歌单

共 **N** 首，来自 **M** 张专辑，发行年份跨度 **YYYY–YYYY**。

## 筛选依据
1. 只取专辑曲目 …
2. 排除非录音室专辑 …
3. 只保留本人演唱/参与 …
4. 跨专辑去重 …
5. 排序 …

**被排除的专辑（K 张）**：《…》、《…》

**无曲目入选的专辑（K 张）**：《…》（原因）

## 曲目清单

| # | 歌曲 | 专辑 | 发行年份 |
|---:|---|---|---|
```

「筛选依据」章节由脚本按**本次运行的实际参数与实际排除结果**生成，不是静态文案，因此不同歌手、不同参数下内容会变化。
